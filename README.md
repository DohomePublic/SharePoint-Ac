# 📋 PO Approval Dashboard (SharePoint → GitHub Pages)

Dashboard สรุปข้อมูล SharePoint List **AC-Data Request for approval of PO**
(site `AC-Accounting`) อัปเดตอัตโนมัติทุกวันด้วย GitHub Actions

🔗 List ต้นทาง: https://dohomegroup.sharepoint.com/sites/AC-Accounting/Lists/ACData%20Request%20for%20approval%20of%20PO

---

## 🔄 วิธีทำงาน

1. GitHub Actions รันทุกวัน **07:00 น. เวลาไทย** (`cron: 0 0 * * *` = 00:00 UTC) — กดรันเองได้จากแท็บ Actions
2. ดึงข้อมูลจาก SharePoint List `AC-Data Request for approval of PO` ผ่าน Microsoft Graph API
3. สร้าง `index.html` ใหม่พร้อมข้อมูลล่าสุด (การ์ดสรุป + กราฟ + ตารางค้นหา)
4. Commit + Push → GitHub Pages อัปเดตอัตโนมัติ

## ⏰ ตารางเวลารันอัตโนมัติ

Workflow ตั้งไว้ที่ `cron: "0 0 * * *"` = **00:00 UTC ทุกวัน = 07:00 น. เวลาไทย**

| ต้องการให้รันตอน (เวลาไทย) | ใส่ cron |
|---|---|
| 07:00 น. (ค่าปัจจุบัน) | `0 0 * * *` |
| 08:00 น. | `0 1 * * *` |
| 09:00 น. | `0 2 * * *` |
| 07:00 น. เฉพาะ จ.–ศ. | `0 0 * * 1-5` |
| 07:00 น. และ 13:00 น. | `0 0,6 * * *` |
| ทุก 1 ชั่วโมง | `0 * * * *` |

สูตรแปลง: **ชั่วโมง UTC = ชั่วโมงไทย − 7** (ถ้าติดลบให้ +24 แล้วเลื่อนไปวันก่อนหน้า)

แก้ได้ที่บรรทัด `- cron:` ใน `.github/workflows/update-dashboard.yml`

> ⚠️ **ข้อควรทราบของ GitHub Actions**: schedule เป็น *best effort* อาจดีเลย์ 5–15 นาที
> ในช่วงที่ระบบมีงานเยอะ และ GitHub จะ **ปิด schedule อัตโนมัติถ้า repo ไม่มี activity นาน 60 วัน**
> (กด Run workflow เองหรือ push ใหม่เพื่อเปิดกลับ)

## 🛠 แก้ปัญหา "เลขที่ / หน่วยงาน ไม่แสดงข้อมูล"

พบ **2 สาเหตุแยกกัน** และแก้ไขแล้วทั้งคู่

### สาเหตุที่ 1 — ชื่อ internal field ไม่ตรง (คอลัมน์ "เลขที่" ว่าง)
Microsoft Graph ส่งคีย์กลับมาเป็น `id` (ตัวพิมพ์เล็ก) แต่สคริปต์เดิมมองหา `"ID"` แบบตรงตัว
และคอลัมน์ที่เคยถูก **เปลี่ยนชื่อภายหลัง** จะมี internal name ไม่ตรงกับ displayName
(เช่น `Department` → `field_4`) ทำให้คอลัมน์ "หน่วยงาน" ว่างเช่นกัน

**แก้แล้วด้วย 4 ชั้น** ใน `pick()`:
1. เทียบชื่อตรงตัวตามรายการใน `FIELDS`
2. เทียบผ่าน map ที่อ่านจาก `/lists/{id}/columns` (displayName ↔ internal name) — ทำงานอัตโนมัติทุกครั้งที่รัน
3. เทียบแบบ normalize (ตัด `_x0020_` / ช่องว่าง / `_` / ตัวพิมพ์เล็ก-ใหญ่)
4. `ID` ว่าง → ใช้ `id` ระดับ item ที่ Graph ส่งมาแทน

เพิ่ม `flat()` แกะค่าจาก object/array ที่ Graph คืนมา (เช่น `{"DisplayName": "..."}` ของช่อง Person)

### สาเหตุที่ 2 — ข้อมูลว่างในต้นทางจริง (คอลัมน์ "หน่วยงาน")
ตรวจข้อมูลจริง 5,791 รายการพบว่า **คอลัมน์ `Department` ว่างอยู่ 2,286 รายการ (39.5%)**
เป็นข้อมูลที่ไม่ได้กรอกมาตั้งแต่ต้นทาง (ปี 2026 = 1,339 · ปี 2025 = 947)
ส่วนคอลัมน์อื่นครบหมด (`_ID`, `Title`, `Site`, `user name`, `PR Number` ว่าง 0 รายการ · `Status` ว่าง 12)

**แก้ด้วยฟังก์ชัน `backfill_dept()`** — เติมหน่วยงานจากคำขออื่นของพนักงานคนเดียวกัน
โดยไล่จับคู่ตามลำดับ **รหัสพนักงาน → อีเมล → ชื่อผู้ขอ** (เลือกค่าที่พบบ่อยที่สุด)

| ผลลัพธ์ | จำนวน | แสดงบนแดชบอร์ด |
|---|---:|---|
| ต้นทางระบุมาแล้ว | 3,505 | แสดงปกติ |
| ระบบเติมให้อัตโนมัติ | 1,467 | แสดงชื่อหน่วยงาน + ป้าย **≈** (ชี้เมาส์เห็นคำอธิบาย) |
| ไม่พบข้อมูลเลย | 819 | แสดง **(ไม่ระบุหน่วยงาน)** ตัวเอียงสีจาง |
| **รวมช่องว่าง** | **0** | |

ผลคือ Top 10 หน่วยงานแม่นขึ้นมาก เช่น สายงานบริการสาธารณูปโภคและซ่อมบำรุง
จาก 1,935 → **2,707** รายการ และเลือกกรอง "(ไม่ระบุหน่วยงาน)" เพื่อไล่ตามให้กรอกข้อมูลได้

### 🔍 เครื่องมือตรวจสอบเมื่อยังมีคอลัมน์ว่าง
1. ทุกครั้งที่รัน สคริปต์จะพิมพ์รายงาน — ถ้าคอลัมน์ไหนว่างเกิน 90% จะขึ้น
   `⚠ คอลัมน์ต่อไปนี้ว่างเกือบทั้งหมด` พร้อมรายชื่อคอลัมน์จริงที่ Graph ส่งกลับมา
   และ workflow จะสรุปไว้ใน **Job Summary** ให้อัตโนมัติ
2. ต้องการดูชื่อคอลัมน์ทั้งหมด: ไปที่ **Actions → Update PO Approval Dashboard →
   Run workflow → ติ๊ก `dump_fields` → Run**
   จะได้รายการ internal name ทุกคอลัมน์พร้อมค่าตัวอย่าง (ไม่แตะ `index.html`)
3. รันบนเครื่องก็ได้: `python scripts/build_dashboard.py --dump-fields`
4. ได้ชื่อจริงแล้ว นำไปเติมใน `FIELDS` ที่หัวไฟล์ `scripts/build_dashboard.py`
